# API Design — PetCare Buddy

Base URL (local): `http://localhost:8000` · Interactive docs (generated by FastAPI): `/docs`

Error responses always use the shape `{"detail": {"code": "...", "message": "ข้อความภาษาไทย", ...}}`.
The UI shows `detail.message` to the customer.

| Method | Path | Purpose | Implementation |
|---|---|---|---|
| GET | `/` | Web chat UI | `app/main.py: index()` |
| GET | `/health` | System status: KB counts, vector store, embedder, LLM configured | `app/main.py: health()` |
| GET | `/api/services` | List all services (optional `pet_type` filter) | `app/routes/services.py` |
| GET | `/api/services/{service_id}` | One service by ID | `app/routes/services.py` |
| GET | `/api/faq` | FAQ list | `app/routes/services.py` |
| GET | `/api/policies` | Customer policies | `app/routes/services.py` |
| GET | `/api/retrieve` | Shows which KB chunks RAG retrieves for a question (evidence/debug) | `app/routes/services.py` |
| POST | `/api/chat` | RAG chat with input/output guardrails | `app/routes/chat.py` |
| POST | `/api/analyze-image` | Image validation + vision model + KB grounding | `app/routes/vision.py` |
| GET | `/api/booking-options` | Opening hours, cancellation notice, services (all from the KB) | `app/routes/booking.py` |
| GET | `/api/availability?date=` | Free and taken hourly slots for one day (times only) | `app/routes/booking.py` |
| POST | `/api/bookings` | Create a booking **request** (status `pending`) | `app/routes/booking.py` |
| GET | `/api/bookings/{id}?contact=` | Customer checks status (id **and** contact must match) | `app/routes/booking.py` |
| POST | `/api/bookings/{id}/cancel` | Customer cancels (≥ 3 hours before, per policy) | `app/routes/booking.py` |
| GET | `/admin` | Staff page | `app/main.py` |
| GET | `/api/admin/bookings` | Staff list (header `X-Admin-Token`) | `app/routes/booking.py` |
| POST | `/api/admin/bookings/{id}/status` | Staff confirm / reject | `app/routes/booking.py` |

## POST /api/chat

**Request (JSON)**
| Field | Type | Rules |
|---|---|---|
| `message` | string | required, 1–1000 chars, not blank |
| `history` | array of `{role: "user"\|"assistant", content}` | optional, max 40 items; server keeps the last 8 turns and drops turns the input guard would block |

```json
{"message": "สุนัขหนัก 12 กิโล อาบน้ำราคาเท่าไหร่", "history": []}
```

**Response 200**
| Field | Meaning |
|---|---|
| `answer` | Thai answer shown to the customer |
| `mode` | `rag` (LLM answer that passed validation) · `guardrail` (input blocked, policy answer from KB, no LLM call) · `fallback` (LLM answer failed output validation and was replaced) |
| `sources[]` | retrieved chunks `{id, title, score, excerpt, cited}`; `cited` = the model listed it in its `SOURCES:` line |
| `safety` | `{input_flags[], output_violations[], blocked}` |
| `provider`, `model` | LLM used (null for guardrail answers) |
| `timings_ms` | `retrieval`, `llm`, `total` |

Example (guardrail path — real output):
```json
{"answer": "ขออภัยค่ะ PetCare Buddy ไม่สามารถเปิดเผยคำสั่งภายในของระบบ ...",
 "mode": "guardrail", "sources": [],
 "safety": {"input_flags": ["system_prompt_extraction"], "output_violations": [], "blocked": true},
 "provider": null, "model": null, "timings_ms": {"total": 0.2}}
```

**Errors**
| Status | code | When |
|---|---|---|
| 422 | `invalid_request` | empty/blank/too long message, malformed JSON |
| 503 | `llm_unavailable` | no API key configured for `LLM_PROVIDER` |
| 502 | `llm_error` | provider error, timeout, auth failure |

**Tests:** `tests/test_api.py` (validation, 503, prompt contains retrieved chunks, invented source IDs dropped, history filtering), `tests/test_safety.py`, `scripts/run_eval.py` (sets A and C)

## POST /api/analyze-image

**Request (multipart/form-data)**
| Field | Type | Rules |
|---|---|---|
| `file` | file | required; real format JPEG/PNG/WEBP (checked by decoding, not by extension); ≤ 5 MB; shortest side ≥ 32 px; images larger than 1568 px are downscaled before being sent to the model |
| `question` | string | optional, ≤ 1000 chars; screened by the input guard |

```bash
curl -F "file=@tests/images/price_sign.png" -F "question=ราคาบนป้ายนี้ถูกต้องไหม" \
     http://localhost:8000/api/analyze-image
```

**Response 200** — as `/api/chat` plus:
| Field | Meaning |
|---|---|
| `observation.image_type` | `dog`, `cat`, `price_sign`, `receipt`, `other`, `unreadable` |
| `observation.observations[]` | only clearly visible details |
| `observation.visible_text` | text read from the image — shown in the UI as *not* official store information |
| `observation.contains_instructions` | true if the image text tries to instruct the bot (adds safety flag `image_contains_instructions`) |
| `image` | `{format, width, height, bytes, resized, ...}` |

**Errors**
| Status | code | When |
|---|---|---|
| 400 | `empty_file` | empty upload |
| 413 | `file_too_large` | > 5 MB |
| 415 | `invalid_image` / `unsupported_format` | not decodable / not JPEG-PNG-WEBP |
| 422 | `image_too_small` / `invalid_request` | < 32 px / missing `file` field |
| 503 | `vision_unavailable` | no API key — message tells the customer the image was **not** analyzed |
| 502 | `vision_error` | provider error |

**Tests:** `tests/test_vision.py`, `scripts/run_eval.py` (set B)

## Booking requests

The chatbot never confirms a queue slot. A request is stored as `pending`; only staff,
through `/admin`, can set `confirmed` or `rejected`. Flow: `docs/diagrams/booking_flow.png`.

### POST /api/bookings

```json
{"pet_type": "สุนัข", "pet_name": "โบ้", "weight_kg": 12, "service_ids": ["S02", "S09"],
 "date": "2026-10-15", "time": "10:00", "contact_name": "ลูกค้าทดสอบ",
 "contact": "081-000-0000", "note": null}
```

Validation (all rules read from `data/knowledge.json`, nothing invented):

| Rule | Source in KB |
|---|---|
| Service id exists, max 4, no duplicates | services |
| Dog-only / cat-only services match `pet_type`; S08–S15 accepted with a warning (pet type not stated) | service names / details |
| Weight required for sized services and inside the range, e.g. S02 = more than 5 up to 15 kg; suggests the right size otherwise | service details |
| Start time is one of the hourly slots 09:00, 10:00 … 18:00 (team decision: last queue starts 18:00; 08:30 / 12:15 / 18:30 rejected), not in the past, at most 60 days ahead (system limit) | `hours` |
| The hourly slot still has room: at most `BOOKING_SLOT_CAPACITY` (default 1) pending/confirmed requests; re-checked inside the database lock when saving; an old 14:30 booking holds the 14:00 slot | bookings database |
| Optional `cat_size` (เล็ก/กลาง/ใหญ่) and `coat_length` (ขนสั้น/ขนยาว), cats only; size derived from `weight_kg` when omitted; surcharges added to `estimated_total` when S04 is booked | `data/cat_pricing.json` |

`GET /api/booking-options` also returns `time_slots` (09:00 … 18:00, every hour), `last_start` and `cat_pricing`.

**201** → `{"booking_id": "PET-BOOK-1710202601", "status": "pending", "status_label": "รอพนักงานยืนยัน", "services": [...], "estimated_total": 550, "contact": "08xxxxx000", "warnings": [...], "message": "..."}`
**422** `booking_invalid` → `{"errors": ["น้ำหนัก 3 กก. ไม่อยู่ในเงื่อนไขของ S02 ..."], "suggestions": [{"id": "S01", ...}]}`
or `{"errors": ["คิวที่คุณเลือกถูกจองแล้ว (วันที่ 2026-10-17 เวลา 11:00 น.) กรุณาเลือกเวลาอื่น"]}`

Staff re-confirming a rejected/cancelled request whose hour has since been booked → **409** `slot_taken`.

### GET /api/availability?date=YYYY-MM-DD

Public, no token, `Cache-Control: no-store`. `date` defaults to today; past dates or more than 60 days ahead → 422 `date_out_of_range`.

```json
{"date": "2026-10-17", "slot_minutes": 60, "capacity": 1,
 "free": ["09:00", "10:00", "12:00", "13:00", "14:00", "15:00", "16:00", "17:00", "18:00"],
 "taken": ["11:00"],
 "free_ranges": [{"from": "09:00", "to": "10:00"}, {"from": "12:00", "to": "18:00"}]}
```

Times only, never who booked them. The booking form uses it to disable booked times; the chat answers
"วันนี้/พรุ่งนี้มีคิวว่างไหม" from the same data without calling the LLM (`mode: "availability"`).
**Tests:** `tests/test_availability.py`.

### GET /api/bookings/{id}?contact=...

Returns the booking only when the contact matches (spaces and dashes ignored). A wrong
contact and an unknown id give the **same** 404 `booking_not_found`, so ids cannot be probed.
Adds `can_cancel` and `cancel_blocked_reason`.

### POST /api/bookings/{id}/cancel

Body `{"contact": "..."}`. **409** `cancel_not_allowed` when less than 3 hours remain
(read from the cancellation policy) or the request is already cancelled/rejected.

### Staff: GET /api/admin/bookings · POST /api/admin/bookings/{id}/status

Header `X-Admin-Token: <ADMIN_TOKEN from .env>`. **503** `admin_disabled` if no token is
configured, **401** `unauthorized` if wrong. Body for status: `{"status": "confirmed" | "rejected", "staff_note": "..."}`;
a cancelled request cannot be confirmed (409).

**Tests:** `tests/test_booking.py`.

## Cat photo estimate

### POST /api/cat-estimate

Multipart `file` (JPG/PNG/WEBP, same checks as `/api/analyze-image`). The vision model returns
JSON describing the cat; the backend normalises it (size follows the weight estimate, weights
clamped to 0.5–12 kg) and computes the price itself — a price written by the model is ignored.

**200** →
```json
{"is_cat": true, "cat_count": 1, "size": "ใหญ่", "size_label": "แมวขนาดใหญ่",
 "weight_kg_min": 5.5, "weight_kg_max": 6.5, "weight_kg_estimate": 6.0,
 "coat_length": "ขนยาว", "confidence": "กลาง", "observations": ["..."],
 "price": {"base_service": {"id": "S04", "price": 500},
           "items": [{"label": "อาบน้ำแมว (ราคาตั้งต้น)", "amount": 500},
                     {"label": "ค่าบริการแมวขนาดใหญ่", "amount": 200},
                     {"label": "ค่าบริการแมวขนยาว", "amount": 150}],
           "total": 850, "suggested_services": [{"id": "S13", "price": 250}], "disclaimer": "..."},
 "message": "ผลประเมินน้องแมวจากรูปค่ะ ..."}
```
Not a cat → `is_cat: false`, `price: null`. **503** `vision_unavailable` without an API key,
**502** if the model output cannot be read, **415/413** for bad files.

### GET /api/cat-pricing?size=กลาง&coat=ขนยาว

The pricing table; with `size` and `coat` it also returns `estimate` (manual choice, no photo).

**Tests:** `tests/test_cat_estimate.py`.

### Chat shortcut

`POST /api/chat` returns `actions: ["open_booking_form"]` when the customer asks to book and
`["open_booking_status"]` for status/cancel questions; the UI shows a button that opens the form.

## GET /api/queue?date=YYYY-MM-DD · GET /api/queue/today

Public, no token. `date` must be today .. today+6 (422 `queue_date_out_of_range` otherwise).

```json
{"date": "2026-10-17", "today": "2026-10-16", "now": "10:05",
 "days": [{"date": "2026-10-16", "active": 2}, "..."],
 "counts": {"pending": 1, "confirmed": 1, "rejected": 0, "cancelled": 0},
 "items": [{"queue_no": 1, "queue_label": "คิวที่ 01", "time": "10:00", "status": "confirmed",
            "status_label": "พนักงานยืนยันคิวแล้ว", "pet_type": "แมว",
            "services": [{"id": "S04", "name": "อาบน้ำแมว"}]}]}
```

Booking numbers (`PET-BOOK-DDMMYYYYnn`) follow a predictable pattern, so the public board shows a
queue number for the day instead and never the booking number, name, contact, pet name, weight or notes.
`Cache-Control: no-store`. **Tests:** `test_queue_today_is_public_and_hides_personal_data`,
`test_queue_board_covers_today_to_six_days_ahead`.

## GET /api/admin/dashboard?start=YYYY-MM-DD&days=7

Header `X-Admin-Token`. Returns totals by status (range and all-time), requests per day with booking
numbers, services booked, estimated revenue of pending + confirmed requests, the busiest day and every
booking in the range (full contact, for staff). Page: `/dashboard`.
