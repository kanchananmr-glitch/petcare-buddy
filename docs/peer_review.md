# บันทึกการตรวจงานสลับกัน (Peer Review)

โจทย์กำหนดให้สมาชิกสลับกันตรวจงานของอีกฝ่าย และทั้งสองคนต้องอธิบายได้ทุกส่วนของระบบ
แบบฟอร์มนี้ให้แต่ละคนกรอกเองหลังตรวจจริง (ห้ามกรอกล่วงหน้า) แล้วสรุปลงรายงานหัวข้อ 16–17

วิธีตรวจแต่ละส่วน: เปิดไฟล์ที่ระบุ อ่านโค้ด รันคำสั่งทดสอบ แล้วลองอธิบายให้อีกฝ่ายฟังว่าส่วนนั้นทำงานอย่างไร

## ส่วนที่ นลินี ตรวจงานของ กาญจนา

| ส่วน | ไฟล์ / คำสั่งที่ใช้ตรวจ | สิ่งที่ตรวจ | ผล (ผ่าน / แก้) | สิ่งที่พบหรือแก้ | วันที่ |
|---|---|---|---|---|---|
| Backend และ API | `app/main.py`, `app/routes/` · `pytest tests/test_api.py` | ทุก endpoint ในแผนภาพมีอยู่จริงและตอบ error ถูกรูปแบบ | | | |
| การวิเคราะห์รูปภาพ | `app/routes/vision.py` · `pytest tests/test_vision.py` | ตรวจชนิดและขนาดไฟล์, ไม่ทำตามข้อความในรูป | | | |

## ซ้อมตอบคำถามรายบุคคล

ให้อีกฝ่ายสุ่มถาม แล้วติ๊กเมื่ออธิบายได้โดยไม่ต้องดูเอกสาร

| คำถาม | กาญจนา | นลินี |
|---|---|---|
| RAG ทำงานอย่างไร ตั้งแต่โหลด knowledge.json จนถึงส่งบริบทให้ LLM | ☐ | ☐ |
| ทำไมใช้ embedding หลายภาษา และ TF-IDF สำรองไว้เพื่ออะไร | ☐ | ☐ |
| input guard กับ output guard ต่างกันอย่างไร ยกตัวอย่างอย่างละ 1 กรณี | ☐ | ☐ |
| ถ้ารูปมีข้อความสั่งให้ลดราคา ระบบป้องกันกี่ชั้น อะไรบ้าง | ☐ | ☐ |
| ทำไมแชทบอทยืนยันคิวเองไม่ได้ ใครยืนยัน และยืนยันผ่านทางไหน | ☐ | ☐ |
| ราคาประเมินแมวคำนวณอย่างไร ทำไมไม่ให้ LLM ตอบราคาเอง | ☐ | ☐ |
| ผลทดสอบข้อที่ไม่ผ่าน (A04, A08, A09) เกิดจากอะไร จะแก้อย่างไร | ☐ | ☐ |
| endpoint ใดบ้างอยู่ในแผนภาพสถาปัตยกรรม | ☐ | ☐ |
